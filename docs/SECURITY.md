# Security review: the qa engine

Issue #15. Scope: the `qa` engine and CLI (`packages/engine`), `qa setup`,
the release and pull request workflows, and the hook template, as of 0.2.3.
Reviewed 11 Nov 2026 against the code in this repository.

## What qa is trusted with

qa runs on developer machines (git hooks) and on GitHub's runners (the pull
request gate). It reads the changed files, runs Gitleaks and Semgrep on a
private copy of them, and reports findings. It never needs credentials, never
changes the repository, and sends data only where it is told to
(`QA_REPORT_URL`).

## Threat model

| Threat                                                                      | Where       | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| qa runs in a repository it must not (personal, other organisations, forks)  | local, CI   | Execution gate (#8): owner `LedgerLink-ai` and listed, enabled, in `registry/repositories.yaml`. In Actions, identity from `GITHUB_REPOSITORY` and the event payload; forks skipped; unverifiable identity fails closed (exit 2). Locally the origin must be a GitHub remote (github.com, or for SSH also ssh.github.com or an alias `ssh -G` resolves to them); an unresolvable alias is not verified. Names compared ignoring case. Fail closed in CI applies to commands run explicitly (`check`, `precommit`, `prepush`, `prepr`, `baseline`); the local hook paths (`hook`, `prepare-commit-msg`, `commit-msg`) skip instead. Tests: `gate.test.ts`, `cli-e2e.test.ts` |
| A pull request weakens the rules it is checked against                      | CI          | Configuration comes from the qa release: `--config`/`QA_CONFIG_DIR` refused in Actions and anywhere inside the repository. In Actions, `--as-of`/`QA_AS_OF`, `--exclude`, `--mode local`, `--actor`/`QA_ACTOR` and `--repo` are refused too (exit 2); the mode is ci and the repository name comes from `GITHUB_REPOSITORY`. The baseline is read from the base branch. `.qa/baseline.sarif`, `.pre-commit-config.yaml`, `.husky/**` are protected paths. Tests: `security.test.ts`, `cli-e2e.test.ts`                                                                                                                                                                      |
| A pull request suppresses its own findings with a baseline                  | CI          | As above: the PR's own `.qa/baseline.sarif` is ignored in CI (with `--base` the base branch's copy is read; without a base the working tree's copy is ignored); a malformed baseline is an error. An expired exemption blocks even when the finding is baselined                                                                                                                                                                                                                                                                                                                                                                                                            |
| Command injection through flags, environment or hook arguments              | local, CI   | No shell anywhere except `repo-script` on Windows, where cmd.exe's special characters inside quotes are refused. Git revisions validated (nothing option-like reaches git). Package, executable and script names validated; executables must be inside their package; `--cwd` inside the repository. Tests: `security.test.ts`, `exec.test.ts`                                                                                                                                                                                                                                                                                                                              |
| A scanner (or a compromised scanner) reads credentials                      | local, CI   | Scanners and git run with credential variables removed (`*TOKEN*`, `*SECRET*`, `*PASSWORD*`, `*PRIVATE_KEY*`, `*API_KEY*`, `AUTH`, ..., and also names ending in `KEY` or `PASS`, containing `_KEY_`, starting with `KEY_`, or containing `MNEMONIC`, `SEED` or `PRIVATE`; `GIT_*`, `SSH_AUTH_SOCK` and `PYTHONHASHSEED` are kept); Semgrep metrics and version checks off. Test: `exec.test.ts`                                                                                                                                                                                                                                                                            |
| Secrets leak into logs, reports or the reporting endpoint                   | local, CI   | Gitleaks runs with `--redact` and messages never carry values; every output path (text, JSON, SARIF, evidence, logs, error messages) passes through redaction; the report token is registered for masking; evidence carries no file contents. Tests: `redact.test.ts`, `publish.test.ts`                                                                                                                                                                                                                                                                                                                                                                                    |
| A tampered qa package                                                       | install, CI | Releases carry a SHA-256 and a Sigstore build provenance attestation from `release.yml`; installers verify both before installing (`npm install --ignore-scripts`). Release tags are protected by a ruleset; release immutability is an administrator setting (docs/OPERATIONS.md)                                                                                                                                                                                                                                                                                                                                                                                          |
| A tampered scanner or Python dependency                                     | `qa setup`  | Gitleaks: SHA-256 from a checksum file kept in this repository. pre-commit, Semgrep and every transitive dependency: `pip --require-hashes --no-deps` from `config/python-requirements.txt`. Downloads https only, no credentials in URLs                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| A moved tag changes what a hook runs                                        | local       | `pre-commit-hooks` pinned by commit SHA in the template; qa pinned by `--require`; every GitHub Action pinned by commit SHA (test enforces)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| A scanner hangs and blocks commits or CI                                    | local, CI   | Time limits per scanner, git command and download; the process tree is killed. Locally deferred to CI; in CI an engine error                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Path traversal from a file name                                             | local, CI   | Files are copied into a private temp directory only if they resolve inside it; paths starting with `-`, absolute paths (including drive letters) and paths containing `..` segments are refused, also in `--files`                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| A change suppresses its own scanner findings                                | local, CI   | `gitleaks:allow` comments (`--ignore-gitleaks-allow`), `.gitleaksignore`, `nosemgrep` comments (`--disable-nosem`) and `.semgrepignore` are ignored; `GITLEAKS_*` variables are dropped. Scanner control files (`.gitleaksignore`, `.gitleaks.toml`, `.semgrepignore`, `.semgrep.yml`, `.semgrep.yaml`, anything under `.semgrep/`) are never copied to the scan directory. Exemptions and the baseline are the only suppressions                                                                                                                                                                                                                                           |
| A file the checks cannot read passes unchecked                              | local, CI   | A file a native check applies to but cannot read as text (binary, over 2 MB, unsupported encoding) is an `unscannable` finding: an error in CI, a warning locally                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| The cache serves a wrong result                                             | local       | Key covers engine version, check, scanner and version, rule-file hash, path and exact content; damaged entries are misses; never used in CI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Workflow token abuse                                                        | CI          | Every workflow defaults to `contents: read`; jobs add only what they need (`security-events: write` for SARIF; `id-token`/`attestations: write` only in the release job)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| A secret committed and removed again inside the pull request                | CI          | `qa prepr` also scans the pull request's commits with Gitleaks (merge base..HEAD), outside the result cache and even when no file changed; a CI job running it needs the full history (`fetch-depth: 0`). Findings name the commit, never the value. No merge base is an engine error (exit 2)                                                                                                                                                                                                                                                                                                                                                                              |
| An AI-made pull request is treated as human (no agent rules)                | CI          | Agent rules when the author is a registered agent or any commit declares AI assistance (`Assisted-by`, or an AI `Co-authored-by` from the registry). Test: `prepr-gate.test.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| A pull request claims its own coverage                                      | CI          | A coverage summary tracked in git is ignored in CI; only coverage the run produced counts. Tests: `prepr-gate.test.ts`, fixture F27                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| An agent edits its own instructions, a workflow, or a scanner's ignore file | local, CI   | `paths.protected`: `ai-config`, `ci-config` and `signing` tags, `.github/**`, `.gitleaksignore`, `.gitleaks.toml`, `.semgrepignore`, keys, secrets and `.env*` (including `.env.example`) block agents, renames (the old path is checked, so moving a protected file away is reported) and deletions included (also a change that only deletes files); humans get a note for code-owner review. Fixtures F05, F19 to F21                                                                                                                                                                                                                                                    |

## Findings of this review and what was done

| #   | Finding                                                                                                              | Severity          | Resolution in 0.2.3                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1   | `--config`/`QA_CONFIG_DIR` could replace the allowlist and policy, including from inside the checked repository      | High              | Refused inside the repository and in Actions (`gate.ts`, `configSourceProblem`)                                  |
| 2   | No enforced pull request gate: the docs said checks "cannot be skipped" on the pull request, but no workflow existed | High              | `qa-pr.yml`, caller stub, rulesets (removed in AIQC-92: pull request checks are handled outside this repository) |
| 3   | A pull request could add its own findings to `.qa/baseline.sarif`                                                    | High              | Baseline read from the base branch in CI; baseline is a protected path                                           |
| 4   | Scanner runs had no time limit                                                                                       | Medium            | Time limits with process-tree kill                                                                               |
| 5   | pip installed pre-commit and Semgrep by version only, dependencies unpinned and unhashed                             | Medium            | Hashed, fully pinned lockfile with `--require-hashes --no-deps`                                                  |
| 6   | Released package had a same-origin checksum only                                                                     | Medium            | Build provenance attestation, verified at install                                                                |
| 7   | Windows `repo-script` quoting let `%VAR%` expand                                                                     | Low               | cmd.exe-special characters refused (`windowsCommandLine`)                                                        |
| 8   | `repo-tool` package names and `bin` paths were not validated                                                         | Low               | Names validated; executable must be inside the package                                                           |
| 9   | Scanners inherited every environment variable, including tokens                                                      | Low               | Credential variables removed                                                                                     |
| 10  | Tool error output was echoed unredacted                                                                              | Low               | Redaction on every output path                                                                                   |
| 11  | `pre-commit-hooks` pinned to a movable tag                                                                           | Low               | Pinned by commit SHA                                                                                             |
| 12  | `qa setup` accepted Python 3.9 and 3.10, where pre-commit 4.7.0 does not install                                     | Low (reliability) | 3.11 to 3.14                                                                                                     |

## Residual risks (accepted)

- **The local gate trusts `origin`.** A developer can point it elsewhere and
  skip local checks. Accepted: local hooks are feedback; pull requests are
  checked outside this repository (docs/ENFORCEMENT.md).
- **Python build dependencies.** If a wheel is missing for a platform, pip
  builds from the (hash-checked) source distribution, and the build tools it
  fetches for that are not hash-checked. All pinned packages ship wheels for
  Windows, macOS and Linux on Python 3.11 to 3.14 today.
- **Repository scripts are the repository's own code.** `qa repo-script` and
  `qa repo-tool` run the repository's tests, linters and build with its own
  dependencies; that is their purpose, and it is no more trust than
  `npm test`.
- **Scanner coverage.** Gitleaks and Semgrep find what their rules describe.
  Rule changes go through review like any other configuration.
